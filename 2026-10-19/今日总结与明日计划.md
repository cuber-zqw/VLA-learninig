## 三、明天（2026-10-20）做什么

主目标：让一个 RoboTwin 专家任务运行起来，保存一条成功演示，理解观测、动作和成功判定之间的关系。

1. **核对依赖和 GPU 兼容性。** 阅读固定版本的 `RoboTwin/script/requirements.txt` 和安装脚本，确认运动规划器与 PyTorch 版本；对 RTX 5060 单独验证 GPU 计算和规划链路。已有 SAPIEN 测试作为基线保留。若必须偏离官方依赖，明确记录修改与复现影响。
2. **准备单个任务。** 选择依赖清晰的简单抓取或搬运任务，检查它的机器人、物体资产和配置，先估算下载量。尽量只准备必要资产；若官方包不能拆分，再决定可接受的下载范围。
3. **跑专家程序。** 先验证机器人能加载、规划能执行，再生成一条成功演示，保存配置、随机种子、视频、日志和数据路径。
4. **打开数据看一眼。** 列出真实数据字段、数组形状、单位和时间对应关系：哪些是图像，哪些是关节状态，哪些是控制目标；具体字段以生成结果为准。
5. **写一个简短复盘。** 解释专家怎样决定抓取位置、规划器怎样生成轨迹、仿真怎样执行动作、程序怎样判断成功。

明天的验收标准：有一段机械臂执行任务的视频；有一条可读取的观测与动作序列；能说清动作表示和成功条件。依赖兼容性若阻塞，则记录最小复现错误和已验证边界，不能把基础渲染通过写成完整任务通过。

后续阶段：积累小批示范 → 教学用小型模仿学习策略 → 保存与加载模型 → 闭环评测。教学策略可先不用语言，因此不应直接称为完整 VLA。完整 LingBot-VLA 的运行与微调留到合适算力条件下，不把 8GB 显存能运行全套系统作为前提。

## 四、你现在最需要理解的整体框架

```text
数据生成：专家程序 → 运动规划与控制目标 → 仿真执行 → 观测与动作示范
模型训练：示范数据 → 预处理和归一化 → 策略训练 → 模型权重
闭环评测：相机图像 + 语言指令 + 机器人状态 → 策略 → 动作
                                                   ↓
                       新观测 ← 仿真步进 ← 控制器执行
```

| 名称 | 在项目中的职责 | 现在要理解到什么程度 |
| --- | --- | --- |
| SAPIEN | 物理仿真与渲染 | `step` 改变物理状态；相机生成图像 |
| RoboTwin | 机器人任务、资产、示范生成与评测平台 | 一个任务怎样配置、执行和判定成功 |
| 专家程序 | 根据任务规则和场景信息生成示范 | 它可能使用真实物体位姿等特权信息，观察权限要查代码 |
| 运动规划器 | 在机器人约束下寻找可执行轨迹 | 目标位姿如何变为运动轨迹 |
| 控制器 | 让机器人跟随关节或末端目标 | 动作是目标，不保证一步后已到达目标 |
| 策略模型 | 根据输入预测动作 | 训练和推理的输入、输出分别是什么 |
| LingBot-VLA | 本项目后续关注的视觉语言动作模型 | 理解模型框架，再研究具体训练实现 |

最重要的五个概念：

1. **观测、状态、动作。** 观测是策略看到的信息；状态是对机器人或环境的描述，其中只有部分可能提供给策略；动作是送给控制链路的命令。物体真实位姿、相机图像和关节目标不能混为一谈。
2. **坐标系与动作表示。** 关节角、末端位置、姿态、夹爪开合的含义不同；世界坐标与机器人基座坐标、绝对目标与增量动作也不同。读数据时必须核对单位和定义。
3. **物理频率、控制频率、图像频率。** 今天每秒 240 个物理步，每隔 8 步录一帧，得到每秒 30 帧。未来模型不一定每个物理步都推理。
4. **模仿学习与闭环误差。** 训练让模型在示范输入上学会预测专家动作；实际执行会改变下一步输入。离线预测误差小，不保证任务成功率高。
5. **训练与评测。** 当前路线以示范监督训练为主；评测成功率衡量执行结果。模型在评测时失败，不会自动学习或更新权重。域随机化用于改变场景条件并检查鲁棒性。

## 五、论文怎么读

现在先能解释流程和输入输出，再逐步补公式。明天建议给阅读留 45～60 分钟，其余时间结合实际任务理解代码。

### 第一步：RoboTwin 2.0，先理解平台

读摘要、总览图、专家数据生成流程、域随机化设计和评测设置。它关注可扩展的数据生成和双臂操作评测；随机化涵盖杂物、光照、背景、桌面高度和语言等因素。[论文](https://arxiv.org/abs/2506.18088)

带着三个问题阅读：专家示范从哪里来？为什么需要改变仿真条件？训练和评测如何区分？暂时不要求读完任务代码生成的所有技术细节。

### 第二步：π0，建立 VLA 的基本认识

读摘要、架构图和方法概览。重点理解预训练视觉语言模型如何与动作生成结合，以及 flow matching 用于生成连续动作这一思路。[论文](https://arxiv.org/abs/2410.24164)

带着三个问题阅读：输入有哪些模态？为什么需要连续动作生成模块？一次预测一段动作后，何时重新观测和推理？公式推导可以等实际接触动作模型时再补。

### 第三步：LingBot-VLA 2.0，对齐最终研究对象

先读摘要、框架图和官方仓库的 Model Design。抓住跨机器人数据、统一动作表示、MoE 动作专家，以及借助深度和视频表征提供几何与未来变化信息的设计。[论文](https://arxiv.org/abs/2607.06403)、[官方实现说明](https://github.com/Robbyant/lingbot-vla-v2#model-design)

第一遍只要求解释这些模块解决什么问题。MoE 路由损失、蒸馏细节、优化器和大规模训练配置，等小型训练闭环跑通后再深入。论文中的完整系统设计，也不能直接等同于我们当前已安装的能力。

### 学到什么程度算够

能用自己的话回答：

- 为什么现在先跑专家，而不是直接训练大模型？
- 一条训练样本的输入和输出是什么？
- 专家可能知道、而策略未必知道的信息有哪些？
- 机械臂动作如何从模型输出落到仿真执行？
- 为什么要在新的初始条件下闭环评测，而不能只看训练 loss？
